# 文档体系重建计划

## 背景

仓库原有文档以根 `AGENTS.md` 和若干模块 README 为主，缺少面向智能体可导航、可分层、可持续维护的整体知识体系。

## 目标

基于“短入口 + 文档目录 + 执行计划一等公件”的思路，为当前 Maven 多模块仓库建立完整文档骨架。

## 范围

- 重写根 `AGENTS.md`
- 新增 `ARCHITECTURE.md`
- 创建 `docs/` 目录下的设计、产品、计划、生成、参考文档

## 非目标

- 不修改 Java 代码
- 不调整 CI / 构建链路
- 不新增自动化文档 lint

## 影响模块

- 根目录文档
- `docs/`

## 风险

- 文档数量明显增加，后续需要持续维护
- 若索引不及时更新，可能再次产生漂移

## 执行步骤

1. 梳理仓库现有结构、模块与流水线事实
2. 定义入口文档与目录结构
3. 写入首批设计文档
4. 写入产品规格文档
5. 写入计划与治理文档
6. 校验链接和层次关系

## 当前状态

- 状态：已完成
- 完成日期：2026-04-11

## 结果摘要

- 根 `AGENTS.md` 已收敛为入口地图
- 已新增 `ARCHITECTURE.md`
- `docs/` 已形成设计、产品、计划、生成、参考五类分层结构
- 既有专题文档已被新的总索引接入

## 决策记录

- 决定保留根 `AGENTS.md`，但收敛为短入口
- 决定新增 `ARCHITECTURE.md` 作为顶层地图
- 决定在 `docs/generated/` 中使用事实占位，而不是伪造业务 schema
