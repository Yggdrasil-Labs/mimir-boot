# 文档治理

文档按读者要完成的任务组织，人和 Agent 共用同一套事实与规则。目标是让读者能找到要改的位置、应遵守的约束和验证方法，并减少重复维护。

## 1. 内容归属

| 位置 | 职责 | 维护方式 |
|---|---|---|
| 根 README、模块 README | 接入方的能力、依赖、配置、示例与限制 | 维护当前使用契约；详细配置归对应模块 |
| `AGENTS.md`、`docs/index.md` | 任务导航与文档地图 | 保留摘要和链接 |
| `ARCHITECTURE.md` | 系统结构、核心基线与依赖方向 | 维护全局架构概览 |
| `docs/design-docs/` | 全局架构、跨模块设计及架构决策 | 主题文档维护当前设计；RFC 保留背景、取舍与批准依据 |
| `docs/standards/` | 核心信条、安全、可靠性与文档治理规范 | 维护必须遵守的当前规则，不复制方案和操作步骤 |
| `docs/engineering/` | 开发、测试、发布与新增 Starter 的操作指南 | 用步骤、表格和必要流程图说明如何工作 |
| `docs/active/` | 当前需求、实施计划与技术债 | 随工作推进更新状态和验收结果 |
| `docs/archive/` | 已结束版本的过程记录 | 保留当时语义，维护必要链接 |

同一易变事实只在一个位置维护，其他页面链接引用。当前产品行为契约由模块 README 承载，原 `product-specs/` 的接入说明并入 README；单次需求的行为变化与验收条件按需写入 `active/` 下的 `spec.md`。

当出现跨模块、长期有效且不适合继续放在 README 的行为契约时，再按需建立 `docs/product-specs/`，并加入总索引。长期规格说明“对使用方承诺什么行为”，设计文档说明“如何实现及为何这样选择”；README 保留使用说明并链接规格，不重复维护契约。当前不创建空目录，也不将建立该目录列为必做任务。

## 2. 按任务规模选择文档

- 局部文字、事实和链接修订：直接修改相关页面并校验。
- 多文件变更、新功能或重构：先形成计划；需求或技术方案复杂时，再分别使用 `spec.md`、`design.md` 表达行为与设计。
- 实质性改变系统边界、依赖方向或长期原则：先在 `../design-docs/` 编写 `arch-*.md` RFC，说明取舍和影响，经批准后实施。
- 验收结果通常记在计划中；证据较多或原计划已有要求时，使用独立 `verification.md`。不为所有任务强制创建整套文件。

任务状态以对应计划为准，保留的版本或需求索引只同步必要摘要，不逐层重复维护状态。RFC 的批准与验证状态用于理解设计决策，不能替代实施进度。既有计划的具体交付要求继续有效。

## 3. 更新触发器

新增或下线 Starter、变更配置默认值、公共 API、依赖方向、构建或发布行为时，同步相应使用契约、设计约束和工程指南。仅更新受影响内容。

代码、POM、工作流和测试是实现事实来源；与文档冲突时先核对实现并回写文档。架构主题、规范和 README 直接维护当前终态，执行过程与历史结论放入需求计划、验收或发布记录。RFC 保留必要的决策依据，日常命令集中到工程指南。

保留核心技术基线和 README 版本徽章；普通依赖与插件版本以 POM 为准，避免在多处重复清单。接入示例、兼容性说明和历史证据中的必要版本号可以保留。

## 4. 导航与阅读

- 新文档应从文档总索引或最近的上级入口可达，不要求每个目录都有 `index.md`。只有需要独立检索或汇总多项内容时才增加索引；单需求版本可由版本页直接链接 spec、design、plan 和验收记录。
- 模块 README 优先服务接入方，仅链接与该模块相关的补充说明；公共工程入口集中在 `AGENTS.md` 和 `docs/index.md`。
- 根 README 不直接引用技术债编号或台账；使用限制在模块文档说明，内部进度由技术债台账跟踪。
- 流程有分支或多个阶段时使用流程图；步骤和命令须同时有文字说明，方便人和 Agent 阅读。

## 5. 迁移与归档

迁移时先确认有效内容已有归属，切换仓库内引用，再删除旧文件；按本次治理约定不保留迁移页或兼容入口。架构 RFC 按跨版本设计价值留在设计库，仅服务单次需求的过程记录归入对应需求目录；不为统一命名机械搬迁，也不改写历史批准和验证结论。

需求完成后同步计划和索引；版本归档时移动对应过程文档并更新引用。归档状态与制品发布状态分别核验。历史正文保留原意，旧命令须明确其历史用途。

## 6. 验证

文档改动校验 Markdown 格式、内部链接和导航，再人工核对职责归属、内容是否遗漏及事实来源。自动检查通过不代表语义与设计意图已经通过审核。

工程检查的执行方式见[测试与质量指南](../engineering/testing.md)。当前仓库没有生成文档目录；未来引入时，在文档索引登记实际产物与生成方式。
