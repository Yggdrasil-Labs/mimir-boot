# 产品感知

Mimir Boot 不是业务应用，而是一个提供工程基线与基础能力的“框架产品”。

决策时优先考虑“接入方体验”，而不是“仓库内部一时方便”。

## 1. 产品目标

- 降低接入方的起步成本
- 提供稳定、可组合、按需引入的基础能力
- 降低版本冲突和重复配置成本
- 提高工程一致性

## 2. 进入门槛

一个能力值得进入 Mimir Boot，通常应同时满足：

- 多项目可复用
- 接入路径明确
- 默认行为可解释
- 长期维护成本可接受

## 3. 决策偏好

优先选择：

- 稳定、可预测、主流的技术方案
- 对使用方侵入性低的自动装配方式
- 默认可用、按需关闭的配置模型

谨慎对待：

- 强侵入式约束
- 高心智负担的配置体系
- 会显著增加发布和兼容性成本的能力

## 4. 产品边界

Mimir Boot 不追求：

- 承担所有企业中间件能力
- 代替业务项目架构设计
- 在单个模块里解决所有问题

它更适合做的是：

- 定义基线
- 提供 starter
- 沉淀通用约定

## 5. 决策自检

做设计决策时，优先问自己：

- 这会让接入方更简单还是更复杂？
- 这是框架层共性，还是业务层特性？
- 这项能力是否应该以独立 starter 暴露？
