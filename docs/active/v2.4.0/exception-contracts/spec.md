# Exception HTTP 与校验错误规格

导航：[需求大纲](./brainstorm.md) · [详细设计](./design.md) · [实施计划](./plan.md) · [版本大纲](../brainstorm.md)

## Overview

统一异常响应在正常可写路径保留应有的 HTTP 状态及协议头；客户端可显式选择结构化校验明细，默认 data 形态保持兼容。

D-36 至 D-38 为既有约束，D-98（空集合与纯 Bean 路径由 400 改为 500）为 2026-10-31 用户确认；除 D-98 外，本文的优先级、配置键、字段与限长均为本轮推荐，尚未实施，不表示用户逐项确认。

状态保留约束针对异常映射与响应工厂：业务码、工厂状态和工厂失败不能覆盖已解析的状态。形成响应后交给原生 MVC；不可表示格式、Resource、条件请求和 Range 请求遵循框架原生处理，不保证这些情况下仍为原状态、完整 body 或空体。

## Behavior E1：标准 HTTP 异常保留状态和协议头

### Scenario：请求方法不允许

Given 请求可正常写出统一响应，接口支持 GET，客户端以不支持的 POST 请求它  
When 生成统一异常响应  
Then HTTP 为 405，Allow 包含 GET，响应 code 为 `20004`  
And 允许的方法不再只出现在消息中；源异常无允许方法信息时不伪造 Allow。

### Scenario：携带合法头的显式状态异常

Given 请求可正常写出统一响应，标准状态异常携带 HTTP 429、Retry-After 为 30、自定义合法响应头 X-Quota 为 0  
When 生成统一异常响应  
Then HTTP 为 429，Retry-After 为 30，X-Quota 为 0  
And 不因框架缺少特定业务错误枚举而改成 500；协议头按异常原值保留，不把内部异常文本作为对外消息。

### Scenario：实体头和非法头

Given 请求可正常写出统一响应，标准异常携带必要响应头，也携带原异常实体的 Content-Type 或非法换行头值  
When 形成 HTTP 响应  
Then 必要合法头和既定状态保留，异常的实体 Content-Type 不直接套到统一响应体上，非法头项不写入  
And 不复制逐跳头或已有实体的长度、编码；实际内容选择与写出沿用框架行为。

## Behavior E2：明确类型优先级和注解作用域

### Scenario：普通业务自定义异常的状态声明

Given 一个普通自定义异常类型声明 HTTP 404，且不属于框架已固定语义的异常类型  
When 它成为当前被处理异常  
Then HTTP 为 404，响应使用既有未找到错误码 `20001`  
And 合并注解及继承的声明同样有效；未显式接入业务错误接口时，不直接输出异常文本或注解 reason。

### Scenario：框架业务和系统异常兼容

Given 一个业务异常或系统异常，包括由 Common 新命名工厂创建的实例  
When 交给默认统一处理器  
Then 业务异常仍为 HTTP 200，系统异常仍为 HTTP 500，已有 code/message 保留  
And 这些框架类型及其子类的固定约定优先于类型上的状态注解；其他基础异常默认 500。

### Scenario：包装异常及处理器覆盖

Given 一个普通包装异常的 cause 声明 HTTP 404，但包装类型自身没有状态声明  
When 默认统一处理器处理该包装异常  
Then 仍返回通用 500，不为寻找状态遍历 cause 链  
And 已由业务更高优先级处理器接管的异常遵循业务实现，本需求不覆盖它；未知异常继续走既有兜底。

## Behavior E3：响应工厂不能覆盖 HTTP 语义

### Scenario：自定义响应体和冲突状态

Given 请求可正常写出工厂 body，已解析的 HTTP 为 405、Allow 为 GET，业务响应工厂返回自己的数据格式，甚至带有 200 状态及冲突 Allow 头  
When 形成最终响应  
Then 保留业务响应体，HTTP 为 405，Allow 仍由源异常确定为 GET  
And 工厂合法的非冲突响应头可以保留，已有过滤器的追踪标识不被无关响应头清空。

### Scenario：工厂抛异常

Given 请求可正常写出默认降级 body，已解析的 HTTP 为 429、Retry-After 为 30，业务响应工厂构建响应体时抛出异常  
When 生成降级响应  
Then 仍返回 429 和 Retry-After 30，响应体降级为框架默认失败格式，使用已确定的 code/message 且 data 为 null  
And 工厂最多调用一次，不递归调用失败工厂，不把工厂异常文本返回客户端。

### Scenario：消费者组合自己的响应能力

Given 消费者配置了自定义响应格式及请求格式选择规则，工厂返回该能力支持的对象或字符串  
When 客户端按该规则请求该格式  
Then 使用消费者实际配置的响应能力输出 body，保留既定状态和头  
And 不把所有工厂结果强制转换为 JSON；内容协商和实际序列化由框架处理。

### Scenario：工厂主动返回null

Given 工厂主动返回 null  
When 生成统一异常响应  
Then 不构造默认失败 body，也不将 null 视为工厂失败，已解析状态和必要头仍交给框架处理  
And 工厂完成之后才发生的内容协商、转换器错误或响应提交后失败，不属于工厂降级机制，不新增超时或客户端断开处理。

### Scenario：无实体状态

Given 已解析状态为 1xx、204、205 或 304  
When 生成统一异常响应  
Then 响应不携带 body，合法协议头仍按合并规则保留  
And 不为这些状态构造统一错误 body；HEAD 继续遵循框架原生处理。

## Behavior E4：输入校验明细按显式模式输出

### Scenario：默认旧格式

Given 未开启结构化明细，字段 name 缺失触发请求体校验，错误消息为“不能为空”  
When 返回校验失败响应  
Then HTTP 为 400、code 为 `00004`，请求体字段校验 data 保持字符串列表如 `["name: 不能为空"]`  
And 绑定异常仍只返回其原消息列表；方法参数与约束校验路径的 data 仍为 null；不改变旧路径顺序、内容或新增对象级条目。

### Scenario：显式结构化输入错误

Given 已开启结构化明细，有字段 name 的非空错误、参数第 0 项的数值错误和对象级跨字段错误  
When 对各自输入校验路径生成响应  
Then data 使用同一包装协议，含完整错误数量、是否截断及错误列表；每项含来源、定位、可空参数序号、约束标识及安全消息  
And 参数名不可用时可定位到 arg0；对象级定位为 `$`；重复错误保留，框架不把拒绝值、请求参数内容或约束参数装入明细。

### Scenario：限长、排序和敏感内容

Given 一次输入校验产生 101 个错误，其中包含集合元素、以实际输入作为键的映射，以及包含原值的自定义插值消息  
When 输出结构化明细  
Then totalCount 为 101，errors 最多 100 项，truncated 为 true，按确定顺序输出；path 最长 256 字符、constraint 最长 64 字符、message 最长 256 字符  
And 映射键位置输出通配符，数值索引可以保留；不输出自定义插值文本或原参数值，未知约束使用通用安全消息。

字段位置无法从允许读取的声明元数据确认时，FIELD 的 path 使用 `$`，不猜测请求内容；方法校验无法区分容器整体约束与元素约束时，定位到参数名。默认旧 data 模式不受这些降级影响。

### Scenario：配置与工厂扩展

Given 结构化开关开启且消费者替换了响应工厂  
When 产生输入校验错误  
Then 使用原工厂接口的 data 参数传入相同结构化对象，HTTP 仍为 400  
And 非法布尔配置使绑定失败；关闭开关恢复旧 data 形态；工厂抛异常时按 E3 降级并丢弃明细。

## Behavior E5：返回值与无法判定来源的约束异常按服务端失败

### Scenario：已知输入参数违例

Given 所有约束违例都能定位到方法参数或跨参数约束，且没有返回值违例  
When 生成错误响应  
Then HTTP 为 400、code 为 `00004`，data 按 E4 的模式选择  
And 不因服务方法校验来自代理而把可确认的输入校验统一当作 500。

### Scenario：返回值及混合违例

Given 方法校验明确指向返回值，或约束路径中至少一项为返回值，即使同时包含输入错误  
When 生成错误响应  
Then HTTP 为 500、code 为 `10000`、message 为“系统错误”、data 为 null  
And 开启结构化明细也不输出返回对象字段、约束消息或返回值。

### Scenario：无法证明为输入

Given 约束异常为空集合，或路径只有普通 Bean 属性、无法定位到参数或返回值  
When 生成错误响应  
Then 返回 HTTP 500、code 为 `10000`、data 为 null  
And 不猜测它是请求参数问题；该规则是用户已确认的明确状态变化（D-98），不提供恢复 400 的开关，需在升级说明中列出，默认旧 data 模式不撤销这项状态判定。

## Behavior E6：统一异常封装保留既有响应追踪增强

### Scenario：可写的默认与降级响应

Given 安装 Web 且响应增强、自动填充均开启，请求上下文的 traceId 为 trace-1，默认失败响应尚无追踪标识

When 输出业务异常、系统异常、普通异常或响应工厂失败后的默认降级响应

Then 可写响应体的 traceId 均为 trace-1，HTTP 分别维持业务 200、系统 500、普通 500 或已解析的工厂失败状态

And 异常响应统一封装不会导致原有追踪增强消失，工厂仍最多调用一次。

### Scenario：既有已缺失追踪标识的分支（审查补充）

Given 安装 Web 且响应增强、自动填充均开启，请求上下文的 traceId 为 trace-1

When 方法参数校验、约束校验、缺请求头、缺路径变量、406、415、413 或静态资源未找到产生可写失败响应

Then 响应体 traceId 为 trace-1，HTTP 状态与现有映射一致

And 这些分支当前已缺失 traceId，属于既有缺陷，随本次联合交付修复并纳入回归。

### Scenario：已有标识与上下文优先级

Given 响应已含 traceId 为 body-1，或空标识响应遇到上下文同时含 traceId 为 trace-1、requestId 为 request-1

When 输出可写的失败响应

Then 前者保留 body-1，后者填 trace-1；仅有 requestId 时填 request-1，两者均无时不生成新标识。

### Scenario：关闭、接管及null边界

Given 响应增强或自动填充关闭，或业务增强器拒绝处理当前响应

When 输出异常响应

Then 不由默认增强补填 traceId；业务替换增强器继续按其自身规则接管

And 工厂返回非公共响应格式或 null 时不强转、不加字段；默认增强不为 null 构造响应，也不改写框架的内容协商结果。

本行为与 [Web W4](../web-binding/spec.md#behavior-w4异常封装保留响应追踪增强) 共用验收；不新增请求标识生成、回传或传播策略。

## Constraints

- 默认结构化开关为 false；旧响应工厂方法、既有 handler public 描述符及原单参构造删除数量为 0。
- 新模式每次最多输出 100 项，固定上限只约束新结构化路径；不回溯截断旧字符串列表。
- 每次异常处理最多调用工厂 1 次，工厂失败重试 0 次；回退 body 与已解析状态、合法协议头一起交给原生 MVC。
- 不增加媒体预判或请求头隔离；不可表示格式、Resource、条件/Range 请求及实际写出失败沿用框架原生处理，不承诺保留原状态或固定空体。
- 仍覆盖现有四类校验入口，不引入安全框架异常、异步超时、客户端断开的新语义；不增加模块、持久化或外部 I/O。
- 本轮不把验证提供器加入 Starter 运行时依赖；需要真实方法校验的测试可在测试范围提供实现。
- E6 的响应增强适配归属 Web；Exception 不新增对 Web 的模块依赖。无 Web 时仍只承诺 Exception 的状态、头和 body 契约，不额外产生追踪标识。
- 升级说明（审查补充）须列出：下游自定义响应体增强在全部异常分支看到的是运行期 ResponseEntity 外层而非 R/Object，按声明类型判断的签名、加密、包装增强可能静默不再生效，须按运行期 body 类型判断；业务的标准状态异常子类会进入新的标准状态分支；子类化统一处理器若以其他方法名重复映射标准状态异常会在启动时报二义映射，仍用原单参构造的子类不读取结构化开关。
- 统一处理器依赖 Servlet 请求对象，仅适用于 Servlet MVC 应用（审查补充）。
- 工厂收到空消息时，按 JSON 空值省略策略可能不输出 message 键；实际输出形态由 Web 联合验收核对。

当前框架版本的方法校验异常只承诺其实际提供的参数、字段与 Bean 全局错误；跨参数明细仅覆盖约束违例异常实际提供跨参数路径的场景，不承诺补回框架未暴露的校验结果。
