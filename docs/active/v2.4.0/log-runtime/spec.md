# Log 日志预设与任务上下文行为规格

## Overview

接入方通过部署模板选择容器或服务器日志预设，在启动阶段获得一致的文本脱敏与可调输出；默认业务执行器传递提交时的日志上下文，自建执行器通过显式入口接入。

来源为[模块讨论](./brainstorm.md)及版本决定 D-28 至 D-34、D-44；Spring Cloud legacy bootstrap 场景按 2026-10-31 用户确认的 D-100；启动机制简化按 2026-11-02 用户批准的 D-101。除 D-100 外，以下具体资源、参数和性能门槛是本轮推荐草案，未代表用户已逐项确认；本轮仅编制 SDD，功能尚未实施。设计与实施入口见 [design](./design.md)、[plan](./plan.md)。

## Behavior: 选择日志预设并保持旧接入兼容

### Scenario: 部署选择容器预设

Given 应用选择容器预设，启用生产环境且未覆盖日志级别
When 普通业务包输出 INFO、WARN 和 ERROR
Then 三条事件各向标准输出写入一次
And 不创建日志目录或日志文件，默认最低业务级别为 INFO

### Scenario: 未选择新预设

Given 应用保留 Starter 自带的原日志配置，未设置新预设
When 应用以生产环境启动并输出普通业务包 INFO 和 WARN
Then INFO 仍被原生产 root WARN 过滤，WARN 沿原控制台与文件路由输出
And 未配置脱敏规则时仍不启用任何规则

### Scenario: 使用其他日志后端

Given 应用排除 Logback，使用可正常启动的其他日志后端，且未选择新预设
When 应用启动、刷新和关闭
Then 新增早期日志入口不加载 Logback 转换器、不启用预置规则，也不引发缺类错误
And 独立 MDC 入口不受预设功能阻断，其记录与传播能力遵循所选后端的 MDC 实现
And Logback 依赖仍在但 Boot 选择其他日志后端或禁用日志系统时，早期预设入口同样退出

### Scenario: 不兼容的后端显式选择新预设

Given 应用缺少 Logback，或者 Boot 选择其他日志后端或禁用日志系统
When 显式选择容器或服务器 Logback 预设
Then 启动失败并明确指出预设需要可用的 Logback 后端
And 不隐式切换后端，不将缺类堆栈当作预设兼容性诊断；Boot 自身更早发现的后端配置错误仍由 Boot 报告

### Scenario: 预设位置的等价写法（审查补充）

Given 部署以 `classpath:` 前缀后带前导斜杠的写法或前后带空白的写法指定容器或服务器预设
When 应用启动并在日志正式初始化后输出 password=alpha
Then 识别为同一新预设，输出与标准写法一致，四组缺省规则生效
And 复制的 XML、文件路径、URL、无 `classpath:` 前缀或前缀大小写不同的写法仍不视为新预设（审查修订）
And 这类写法以预设文件名结尾时，启动日志有一条信息级提示说明未启用预设缺省规则

### Scenario: 配置资源不存在

Given 部署指定的日志配置资源不存在
When 应用启动
Then 启动失败并报告日志配置位置
And 不静默回退到旧配置或另一预设

## Behavior: 路由业务、访问与 SQL 日志

### Scenario: 服务器分流

Given 应用选择服务器预设，业务日志和访问日志均启用，SQL 日志已有生产者
When 分别输出普通 INFO、普通 ERROR、访问 INFO、普通 SQL INFO 和慢 SQL WARN
Then 普通 INFO 进入 info.log 一次，普通 ERROR 分别进入 info.log 和 error.log 各一次
And 访问 INFO 只进入 access.log，普通 SQL INFO 与慢 SQL WARN 各进入 sql.log 一次
And 所有事件均不向标准输出复制

### Scenario: SQL 记录未启用

Given 应用选择任一新预设，普通 SQL 日志生产开关关闭
When 执行一条未超过慢阈值的 SQL
Then 不产生普通 SQL 日志
And 选择预设不会改变 SQL 日志生产开关或 SQL 日志消息结构

### Scenario: 标准输出写入异常

Given 应用选择容器预设，标准输出发生 I/O 错误
When 输出业务 ERROR
Then 应用不创建文件作为隐式备用出口
And 后端能够检测到的错误保留原有诊断；底层吞掉写入异常时可能没有后端错误状态，不承诺主动探测或逐事件失败计数
And 无异常、无错误状态均不能作为该事件已成功写出或被采集的证据

### Scenario: 文件输出发生可检测错误

Given 应用选择服务器预设，文件输出遇到后端能够检测的权限或写入错误
When 后端尝试打开或写入该文件
Then 保留后端错误诊断，不切换到标准输出或其他隐式备用出口
And 不将业务调用未抛错视为日志送达成功

## Behavior: 调整滚动、队列与级别

### Scenario: 部署覆盖日志参数

Given 服务器预设将单文件上限改为 50MB、普通文件保留改为 7 天、队列容量改为 2048
When 应用启动并输出日志
Then 四类文件的单文件上限为 50MB，info.log、access.log、sql.log 的保留策略均为 7 天，error.log 仍按其独立保留设置，四个异步队列容量为 2048
And 应用无需复制整份日志配置

### Scenario: 覆盖第三方降噪

Given 新预设的生产环境将 org.springframework 默认设为 WARN
When 接入方将 org.springframework 的日志级别显式设为 INFO
Then org.springframework.context 的 INFO 事件可以输出
And 新预设不另设更具体的 Spring INFO 或 WARN 级别阻碍该覆盖

### Scenario: 队列满与无效参数

Given 服务器预设使用默认队列策略，输出线程被暂停且队列已满
When 业务线程继续输出日志
Then 提交线程等待队列空间，不主动丢弃低等级或高等级事件
And 显式改为非阻塞策略后允许任意等级事件在队列满时丢失
And 容量为 0、负保留天数等无效配置在启动时失败并指出属性名

## Behavior: 从日志正式初始化起执行凭据字段脱敏

### Scenario: 新预设默认脱敏

Given 选择任一新预设且未显式设置脱敏规则
When 在日志正式初始化后、业务 Bean 创建期间以及上下文刷新后分别输出 password=alpha token=beta secret=gamma api_key=delta
Then 每个阶段输出中的四个值均为 ****，且不包含 alpha、beta、gamma、delta
And 异常消息与异常原因链中的同类字段使用相同规则

### Scenario: 启动失败堆栈与关闭阶段日志仍脱敏（审查补充）

Given 选择任一新预设且未显式设置脱敏规则
When 业务 Bean 创建时抛出消息含 password=alpha 的异常导致启动失败，或应用关闭时在销毁回调中输出 token=beta
Then 框架输出的启动失败堆栈与关闭阶段日志中两个值均为 ****
And 启动失败或关闭不导致脱敏回退为空规则；下一次选择新预设的独立启动只使用自身配置（下一次启动为旧配置时，其上下文刷新后才只使用自身配置，D-101）

### Scenario: 启动期并发输出不出现空规则（审查补充）

Given 同一进程中前一应用以含 password 的规则运行后已关闭，下一应用选择新预设并开始启动，另一线程持续输出 password=alpha
When 下一应用加载日志配置并切换为本次规则
Then 该线程已输出的每一行都不含 alpha（日志系统初始化期间被拒绝的事件不输出，不要求每次调用都产生一行）
And 本次配置校验失败时启动终止，进程中已生效的规则保持不变（D-101 修订）

### Scenario: 刷新前调用编程式规则入口（审查补充）

Given 选择任一新预设且未显式设置脱敏规则
When 业务 Bean 创建期间调用既有的追加自定义规则或重新加载规则入口，随后输出四类字段
Then 四组缺省规则仍然生效，追加的规则同时生效
And 不需要等待上下文刷新完成

### Scenario: 显式覆盖或关闭

Given 选择新预设，将启用规则显式设为空列表，且无自定义或编程式规则
When 输出 password=alpha
Then 输出保留 alpha
And 将规则改为仅 password 后只遮蔽 password，不自动追加其余三组

### Scenario: 应用默认属性中的显式规则

Given 接入方通过 SpringApplication.setDefaultProperties 显式设置仅 password，或将启用规则设为空列表
When 分别在日志正式初始化后、业务 Bean 创建期间和上下文刷新后输出四类字段
Then 单规则配置始终只遮蔽 password，空列表配置始终不启用预置规则
And 应用默认属性中的其他键保留不变，索引列表或空字符串写法遵循相同覆盖与关闭语义
And 更高优先级配置源的显式列表整体覆盖应用默认列表，不与四组缺省规则合并
And 未配置列表时，新预设三个阶段均使用四组规则；顺序启动复用环境并改回旧配置时，旧配置应用上下文刷新后不启用预置规则（刷新前可能沿用上一应用规则，D-101）

### Scenario: 新预设规则配置无效

Given 选择新预设且自定义规则包含非法正则、预置规则名为 unknown-rule，或自定义规则/替换字符含无法解析的 `${` 占位符（D-101）
When 应用准备初始化日志
Then 启动失败并指出规则属性及规则序号（替换字符为单值属性，只指出属性名）
And 诊断中不回显规则原文、原始业务日志或秘密
And 旧配置沿用既有无效规则处理，不因新预设而改变

### Scenario: 普通子上下文复用父日志

Given 父应用选择新预设并已启动，子上下文仅复用父日志，不另行启动应用级日志生命周期（子上下文可含日志自动配置并声明自身脱敏属性）
When 子上下文刷新失败或关闭，随后创建并刷新另一个子上下文
Then 父应用的日志级别、输出出口和脱敏规则保持不变
And 父应用关闭后，下一次选择新预设的独立应用启动使用自身配置，不残留上一轮规则（下一次启动为旧配置时，其上下文刷新后才只使用自身配置，D-101）

### Scenario: 开启 Spring Cloud legacy bootstrap（D-100）

Given 应用开启 Spring Cloud legacy bootstrap，bootstrap 配置不含日志设置，`application.yml` 选择任一新预设且未显式设置脱敏规则
When 应用启动并在日志正式初始化后、业务 Bean 创建期间以及上下文刷新后分别输出 password=alpha token=beta secret=gamma api_key=delta
Then 每个阶段四个值均为 ****，与未开启 bootstrap 时一致
And 未选择新预设、仅在 `application.yml` 配置启用规则的旧接入者，刷新后仍按该配置脱敏，行为与升级前一致
And bootstrap 阶段不改变主应用的规则，运行期配置刷新也不改变当前规则

### Scenario: 部署模板经系统属性或环境变量选择预设并开启 legacy bootstrap（审查补充）

Given 应用开启 Spring Cloud legacy bootstrap，部署通过系统属性或环境变量选择任一新预设
When 应用启动
Then bootstrap 阶段加载该预设不因缺少预设参数而启动失败，使用预设默认参数
And 主应用日志正式初始化后、Bean 创建期间和上下文刷新后四组缺省规则均生效，主应用的预设参数覆盖生效
And bootstrap 阶段输出不在承诺的保护起点内；加载预设时按四组缺省脱敏（D-101）

### Scenario: 运行期配置刷新含无效预设规则（D-101）

Given 选择新预设的应用正在运行且未开启 Spring Cloud legacy bootstrap（使用 ConfigData 刷新），配置中心推送的脱敏规则含 unknown-rule 或非法正则
When 触发运行期配置刷新
Then 该次刷新失败并指出规则属性及序号，不回显规则原文
And 当前脱敏规则与日志输出保持不变

### Scenario: 同一进程中缓存多个测试应用（审查补充）

Given 测试框架在同一进程中先后启动并缓存两个配置不同的应用，第一个仍未关闭
When 第二个应用启动并输出日志
Then 第二个应用启动不报错，其规则与参数的绑定、校验按自身配置执行（D-101 修订）
And 第二个应用上下文刷新后，进程内脱敏规则为最后刷新应用的规则，与旧配置“最后刷新者发布”一致（D-101 修订）
And 未引入 Spring Cloud 上下文组件时，第二个应用沿用第一个应用已加载的日志输出出口与文件/队列参数，自身不同的预设不重新加载；其上下文刷新前进程内规则仍为前一应用的规则
And 引入 Spring Cloud 上下文组件（含经 Feign Starter 传递引入）时，第二个应用按自身预设与文件/队列参数重新加载日志输出，第二个应用选择新预设时重新加载后即使用其规则，为旧配置时其上下文刷新后才使用其规则
And 关闭第一个应用后再启动的新预设应用使用自身配置（下一次启动为旧配置时，其上下文刷新后才只使用自身配置，D-101）；接入说明分别列出两种行为及隔离方式

## Behavior: 默认业务任务传递完整日志上下文

### Scenario: 提交时快照

Given 默认业务执行器已接入传播，提交线程具有 traceId=t1、tenantId=a、customKey=x
When 提交任务后将 tenantId 改为 b，再允许任务执行
Then 任务看到 traceId=t1、tenantId=a、customKey=x
And 执行结束后工作线程恢复执行前的完整上下文

### Scenario: 空上下文、嵌套和同线程执行

Given 提交线程没有任何日志上下文字段，工作线程原有 stale=old
When 执行该任务，再在任务中提交嵌套任务或由提交线程直接执行包装任务
Then 外层任务执行期间看不到 stale
And 每层任务退出时恢复各自进入前的上下文，后续独立任务不会继承前一任务新写入的字段

### Scenario: 任务失败与拒绝

Given 工作线程原有 worker=w，提交快照为 requestId=r
When 任务写入 temporary=v 后抛出 IllegalStateException
Then 异常保持原有传播方式，退出后上下文只保留 worker=w
And 被执行器拒绝的任务保持原拒绝语义，提交线程上下文保持不变

## Behavior: 与业务执行器扩展协作

### Scenario: 唯一业务装饰器

Given 接入方使用框架自动配置的执行器及其构建器，已有一个业务装饰器，未提供其他执行器定制器
When 提交任务
Then 业务装饰器与日志上下文传播均执行一次
And 不修改线程池容量、线程名、拒绝策略、关闭策略等既有参数

### Scenario: 多个业务装饰器

Given 接入方使用框架自动配置的构建器，已有两个业务装饰器，未提供其他执行器定制器
When 默认业务执行器初始化并执行任务
Then 日志上下文传播仍生效
And 有唯一优先候选时仅该业务装饰器执行一次；没有唯一候选时两个业务装饰器均不执行，保持框架原选择行为
And 不根据顺序自动组装全部业务装饰器，也不增加普通业务装饰器候选数量

### Scenario: 业务定制器优先

Given 接入方提供新式或旧式执行器定制器，直接设置业务装饰器或仅修改线程池参数
When 默认执行器初始化
Then MDC 自动适配退让，不改变业务定制结果，也不要求调整定制器顺序
And 启动日志中有一条信息级说明指出默认执行器未自动传播日志上下文及显式接入方式
And 未显式组合时不承诺新增 MDC 传播；在业务定制器中使用已有统一组合入口后，业务装饰器及 MDC 各执行一次并恢复上下文

### Scenario: 自定义执行器构建器

Given 接入方只提供自定义构建器而没有声明执行器
When 框架使用该构建器创建默认执行器
Then 自动传播适配退出，不承诺该构建器自动消费框架定制器
And 接入方显式使用统一组合入口后，任务才按快照与恢复契约传播上下文

### Scenario: 自建执行器或关闭传播

Given 接入方声明自建执行器，或者显式关闭默认业务执行器传播
When 启动应用并提交普通任务
Then 不替换、重配置或遍历改写该自建执行器，关闭时恢复原默认执行器路径
And 自建执行器只有显式使用统一包装或组合入口的任务才传播上下文
And 对空任务使用统一入口时立即拒绝，不能吞掉任务或返回空包装结果

## Constraints

- 兼容基线为 Java 17、Spring Boot 3.3.13；自动接入限于无其他执行器定制器、使用自动配置构建器的平台默认业务执行器，覆盖 execute/submit 和使用该执行器的异步方法。自定义执行器、构建器或定制器使用显式入口；不承诺虚拟线程、原生 Thread、通用线程池或调度任务自动接入；因其他定制器退让或虚拟线程模式而未自动接入时，启动日志给出一条信息级说明（审查补充）。
- 新预设生产 root INFO；生产降噪为 13 个既有有效前缀；未选择新预设时新增文件与新增默认脱敏规则数量均为 0。
- 同一事件在同一出口出现 1 次；ERROR 同时进入服务器 info.log、error.log 是明确的双出口归档，不属于重复写同一出口。
- 脱敏仅覆盖已有文本标量字段能力；不承诺完整 JSON、对象、数组、JVM 标准错误原始输出或日志正式初始化前的输出。MDC 传播不创建或恢复 tracing Span。
- 父子保障限于普通子上下文共享父应用日志；同一类加载器中另行启动子 SpringApplication 会建立自己的 Boot 日志生命周期，其启动、失败、重试不在自动保护范围内。需要独立日志生命周期时由接入方隔离应用进程；本轮不接管 Boot 全局日志监听器。
- 输出故障诊断限于后端实际检测到的错误；标准输出底层可能吞掉写入异常，日志采集成功须由采集端另行验证。
- 推荐性能验收门槛：在同机同参数、至少 3 轮预热后对照中，1KiB 消息的四组规则吞吐不低于关闭规则的 80%，P99 不高于关闭规则的 125%；命中与不命中分别报告。该门槛为设计目标，尚无测量结论；异常栈、64KiB 长消息、实际控制台/文件和队列满场景另报数据，不将纯转换结果外推。
