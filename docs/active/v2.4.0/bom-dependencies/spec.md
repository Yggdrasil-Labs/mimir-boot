# BOM 配套依赖需求规格

本稿是 v2.4.0 推荐规格，未实施；D-16、D-17、D-18、D-67 已确认，其余具体方案为本轮推荐。[讨论来源](./brainstorm.md) · [设计](./design.md) · [计划](./plan.md)

## 目标与边界

让下游按需选择三个配套组件，并以统一版本组合编译和运行。不增加模块、不扩大 COLA 托管范围、不升级框架基线。

## Behavior B1：按需获得受管版本

| Scenario | Given | When | Then |
|---|---|---|---|
| 正常接入 | 消费者采用本次发布的依赖基线 | 无版本声明地选择 OOXML 组件 | 解析为 5.5.1，与基础 POI 一致，文本和数值工作簿可写入并重新读取 |
| 传递版本 | 消费者选择 OOXML 组件，同时导入 Boot 3.3.13 依赖管理 | 检查有效依赖树 | 记录 log4j-api、commons-io、commons-compress、xmlbeans 的实际版本及来源；本轮不在 BOM 覆盖，结果作为证据 |
| 未选择组件 | 消费者只导入基线 | 检查运行依赖 | 不新增 binding、OOXML、COLA DTO 三个组件 |
| 显式覆盖 | 消费者自身明确管理同一坐标版本 | 解析依赖 | 采用消费者版本；兼容性由覆盖方负责，不承诺任意覆盖都可运行 |
| 缺失制品 | 独立仓库无法提供所需受管版本 | 解析依赖 | 构建失败并保留缺失坐标，不自动切换版本或扩大依赖范围 |

## Behavior B2：两种消费方式均可组合使用

| Scenario | Given | When | Then |
|---|---|---|---|
| 继承接入 | 消费者继承本次发布 Parent | 选择属性生成、对象映射及 binding 配套组件并编译 | 生成的映射实现读取生成属性，映射值与输入相同 |
| 独立导入 | 消费者只导入本次发布 BOM，自己配置编译器 | 使用相同组件与样例 | 解析同一组受管版本并完成映射；不获得 Parent 的插件/profile |
| 独立显式开启处理（审查补充） | 独立导入方在 JDK 25 上自行开启注解处理（`maven.compiler.proc=full` 或 `-proc:full`，推荐 JDK `[23,)` 激活的 profile） | 使用相同组件与样例 clean compile | 编译成功，Lombok 属性与 MapStruct 实现均生成并完成映射 |
| 独立编译失败 | 独立导入方在 JDK 25（JDK≥23 的 javac 默认不执行注解处理）上未开启处理 | 编译引用生成类型的样例 | 明确编译失败，不将仅有版本管理描述为自动开启处理 |

## Constraints

- 新增托管坐标恰为 3 个；不导入 COLA 全量 BOM。
- COLA DTO 固定 5.0.0（D-67）；POI 沿用仓库 5.5.1；binding 推荐 0.2.0，实施时完成许可证和组合验收。
- Boot 3.3.13、Cloud 2023.0.6、Alibaba 2023.0.3.4 保持现有基线，不承诺本轮完成全部依赖的安全支持评估。
- 两种消费方式分别验证，reactor 构建不能替代发布形态的独立消费者。
