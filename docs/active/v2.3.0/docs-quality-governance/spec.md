# Agent 文档治理与本地质量门禁 — 需求规格

## Overview

Agent 能从唯一入口找到当前有效的开发契约；维护者使用统一检查入口，在提交和推送之前发现格式、文档结构、测试及覆盖率问题。已确认方向在本规格中转为可验收行为；文档状态不表示功能已经实现。

## Behavior: B1 按任务找到唯一权威文档

### Scenario: B1-S1 开发任务导航

Given Agent 需要修改依赖、新增 Starter、修改配置或执行发布
When 从仓库 Agent 入口按任务导航
Then 每类任务均能找到约束、操作步骤和验收方法
And 同一使用契约只指定一个权威来源，其他文档通过链接引用。

### Scenario: B1-S2 人类接入方阅读

Given 接入方仅阅读仓库和模块 README
When 选择能力并按示例接入
Then 能找到必要依赖、启用条件、默认行为及限制
And 无需阅读技术债台账才能完成接入，根 README 不包含台账链接或 TD 编号。

### Scenario: B1-S3 文档不可达或重复

Given 新增有效文档未被入口发现，或两个页面重复维护配置默认值
When 执行文档结构检查和权威来源审查
Then 不可达文档由自动检查列出，重复事实由内容审查列出
And 两类发现均定位到文件，自动结构检查不冒充代码语义审查。

## Behavior: B2 显式初始化开发检查环境

### Scenario: B2-S1 首次初始化

Given 本机有项目要求的 Java 和 Git，没有全局文档检查运行环境
When 显式初始化当前仓库的开发检查环境
Then 项目专用检查工具就绪，提交和推送检查启用
And 用户得到工具版本、安装路径及 hook 状态的结果。

### Scenario: B2-S2 重复初始化和多个工作树

Given 本仓库检查环境已初始化，且存在多个工作树
When 再次执行初始化
Then 相同配置保持幂等，各工作树使用自己的受版本管理的 hook 文件
And 不覆盖其他仓库配置，不删除工作树，不改变工作区和暂存内容。

### Scenario: B2-S3 下载失败或已有 hook 冲突

Given 工具下载失败、版本校验失败或存在不兼容的自定义 hook
When 执行初始化
Then 返回失败并说明原因
And 不将未就绪状态报告为成功，不静默覆盖已有 hook 或启用失效 hook。

## Behavior: B3 文档检查给出可信结果

### Scenario: B3-S1 格式、链接和结构合格

Given 被检查版本中的 Markdown、内部链接、导航和台账满足规则
When 执行完整文档检查
Then 所有必需检查均记录为通过，命令返回成功。

### Scenario: B3-S2 仅有人工复核提示

Given 文档满足强制规则，但存在待核对发布状态的归档提示
When 执行完整文档检查
Then 提示单独列出，不阻止其他检查执行，不将历史版本自动归档。

### Scenario: B3-S3 多项独立错误

Given 一个文件存在列表格式错误，另一个存在失效锚点
When 执行完整文档检查
Then 两项独立检查均产生结果并定位错误
And 总体返回失败，未执行的检查不标记为通过。

### Scenario: B3-S4 工具不可用

Given 必需工具缺失或检查进程异常退出
When 执行完整文档检查
Then 结果标记为执行错误或未执行，总体失败并给出恢复指引。

## Behavior: B4 提交前检查实际暂存内容

### Scenario: B4-S1 格式合格的提交

Given 暂存内容中的 Java 和 Markdown 格式合格
When 正常提交
Then 快速检查通过后才创建提交，检查不运行完整测试套件。

### Scenario: B4-S2 部分暂存

Given 已暂存的内容存在错误，而工作区中同一文件已修复但没有重新暂存
When 正常提交
Then 提交被阻止，错误指向暂存版本
And 工作区、暂存区和未跟踪文件均保持原样。

### Scenario: B4-S3 格式错误或工具缺失

Given 暂存 Java 存在格式错误，或格式检查工具不可用
When 正常提交
Then 不创建提交，返回具体原因
And 不自动格式化文件，不自动暂存修复。

## Behavior: B5 推送前验证实际待推送版本

### Scenario: B5-S1 完整质量验证

Given 待推送版本通过文档、格式、编译、测试、覆盖率和报告核验
When 正常推送
Then 全部门禁通过后才允许更新远端引用。

### Scenario: B5-S2 工作区与推送目标不同

Given 当前工作区已修复问题，但待推送引用指向包含错误的提交
When 推送该引用
Then 使用该引用对应的版本检查并阻止推送
And 不将当前工作区的成功结果用于该提交。

### Scenario: B5-S3 多个引用、新分支与删除

Given 一次推送包含多个引用或新分支
When 执行推送检查
Then 每个不同的目标内容快照均被验证，任一个失败就阻止整次推送
And 仅删除引用时记录为无新增内容，不执行无意义构建。

### Scenario: B5-S4 必需检查未完成

Given 编译失败，导致测试和覆盖率无法执行
When 推送检查汇总
Then 编译记录为失败，依赖它的检查记录为未执行，整体失败。

## Behavior: B6 代码质量门禁使用完整的新鲜证据

### Scenario: B6-S1 测试与覆盖率达标

Given 应执行的测试全部成功，适用模块指令覆盖率不低于 60%、分支覆盖率不低于 50%
When 执行完整构建质量验证
Then 格式、测试和覆盖率门禁通过
And 最终覆盖率报告包含本次单元测试与集成测试产生的数据。

### Scenario: B6-S2 无源码模块与覆盖率边界

Given 某模块为纯构建描述模块，另一个适用模块恰好达到覆盖率阈值
When 核验报告和门槛
Then 无源码模块按显式规则豁免并记录原因，达到阈值的模块通过
And 不因其他模块有报告就忽略应有报告但缺失的模块。

### Scenario: B6-S3 格式、测试或覆盖率不合格

Given 任意受检子模块格式不合格、测试失败、测试被跳过或覆盖率低于阈值
When 执行完整质量验证
Then 对应门禁失败，不能仅凭构建进程返回成功认定检查通过。

### Scenario: B6-S4 报告缺失或过期

Given 应产出的测试或覆盖率报告缺失，或仅存在上次构建遗留报告
When 核验构建产物
Then 拒绝通过并定位缺失模块或过期证据。

## Behavior: B7 本地与 CI 使用相同判定规则

### Scenario: B7-S1 同版本同输入

Given 本地与 CI 检查同一内容版本且所需环境均就绪
When 执行共享的质量检查流程
Then 使用相同工具版本、规则、阈值和扫描边界
And 确定性违规的结论一致。

### Scenario: B7-S2 远程专属分析

Given 本地没有远程分析凭证
When 完成本地质量检查
Then 本地门禁可独立完成，远程专属分析显示为不适用
And CI 仍按既有事件与凭证条件执行远程分析。

### Scenario: B7-S3 本地检查被绕过

Given 含有违规的提交通过其他方式进入 CI
When CI 执行共享检查
Then CI 独立拒绝该版本，不信任本地成功声明或本地报告缓存。

## Behavior: B8 迁移文档并保留历史语义

### Scenario: B8-S1 当前文档迁移

Given 文档迁移矩阵列出每份有效文档的目标职责
When 完成迁移和内容归并
Then 每份原文档均有明确去向，所有当前引用可达
And 使用契约、开发约束、操作步骤有独立的权威位置。

### Scenario: B8-S2 历史文档引用旧路径

Given 归档记录链接到即将移动的长期文档
When 更新路径或兼容锚点
Then 链接恢复可用，当时的行为、日期、版本和验证结论保持原义。

### Scenario: B8-S3 发布尚未确认

Given 需求本地验收完成，但远程制品发布状态没有证据
When 整理活跃版本和归档目录
Then 仍保留发布待核对状态，不以标签、开发版本回写或目录迁移认定发布成功。

## Constraints

- 当前采用 Java 17；不调整已确认的 Spring Boot/Cloud 技术基线。
- 沿用指令覆盖率 0.60、分支覆盖率 0.50；覆盖率按适用模块判定，保留既有排除口径并审计其必要性。
- 首版提交前只做快速检查；推送前全量验证，不因纯文档修改静默省略完整门禁。
- 版本规划目录为 v2.3.0；不据此修改根 POM 的 2.2.2-SNAPSHOT、标签或发布策略。
- 本地和 CI 的强制检查不依赖个人技能目录、历史临时日志或全局 Node 安装。
- 全局文档维护终态；核心版本和 README 徽章保留；普通依赖版本只在配置和必要的历史证据中维护。
- 只读检查不得改变源文件、暂存内容、未跟踪文件或当前分支；缓存与报告写入独立忽略目录。
- 本地 hook 可被显式绕过，CI 保留最终质量判定；本需求不改变远端分支保护配置。
- 不承诺未测量的运行时长；验收记录首次准备与缓存命中后的实际耗时。
