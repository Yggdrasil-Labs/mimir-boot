# 技术债务追踪

本清单只记录仍处于活跃状态、需要后续设计、修复、兼容迁移或明确接受的技术债务。条目按编号升序排列；已关闭债务的表格行和明细均移除，处理结果与验收证据归入对应计划或验收记录；没有独立计划时由版本 release 记录承接。

## 维护规则

- 新增债务时核对本页、历史计划和版本记录，以历史已分配最大编号加一生成 `TD-xxx`；关闭或删除后不得复用编号。
- 每项补全领域、优先级、状态、Owner、记录日期、处置与验收条件、目标版本及复查条件。未确定目标版本时明确填写 `待排期`，不得把文档目录编号当作发布承诺；Owner 在每月架构回顾及条目列出的触发条件发生时复查。
- **高**：存在发布消费者不可用、数据泄露、配置错误或核心行为错误的风险，应优先纳入最近迭代。
- **中**：质量门禁、测试可靠性或兼容性存在缺口，需要排期处理。
- **低**：影响受限的兼容包袱或测试维护项，可随相关改动一并处理。
- `兼容保留` 表示框架已规避内部主路径，但公开旧接口仍保留已知风险；只有完成迁移或废弃后才能移除。
- `部分修复` 必须明确剩余风险；`验收中` 必须区分已有证据和未闭环条件。配置修改或普通构建通过不能替代专项验收。
- 关闭前核对实现、适用验收和剩余风险结论。风险接受须记录 Owner、原因、影响边界及重新评估条件，不能把接受风险写成已修复。
- 清理已关闭项前，先确认完整记录已有归属、切换仓库内引用，再删除台账明细及旧锚点；不保留兼容入口。历史执行和验收结论保留原意，后续迁移另记决策。
- 债务关闭与制品发布分开记录：满足约定验收范围即可关闭，`未发布` 由 release 记录跟踪。本地结果不得写成 CI、真实发布或发布后消费者已验证。
- Owner 不明确时填写 `ORPHAN`；30 天内未指派的条目应在架构回顾中决定归档、删除或分配维护者。

## 债务明细

<a id="td-013-rpc-mdc-scope"></a>

### TD-013：RPC MDC scope 兼容入口

- **现状与风险**：`MdcRpcTracerBridge.extract()` 的非 scope 入口不回滚 MDC；自定义 Bridge 只实现 `extract` 时仍可能泄漏上下文。
- **已缓解范围**：框架内部调用已迁移到调用级 scope，旧入口仅为兼容保留（证据：`bf493b6`、`2dd1b83`、`4e428e6`）。
- **处置与验收**：完成旧入口迁移或废弃，并验证自定义 Bridge 异常、嵌套调用和异步调用后 MDC 均被恢复。
- **目标版本**：待排期。
- **复查条件**：RPC Trace API 迁移、废弃或相关生命周期调整时，核对公开旧入口和自定义 Bridge 的剩余风险。

<a id="td-016-字段加密-aad"></a>

### TD-016：字段加密 AAD 绑定

- **现状与风险**：字段加密没有字段或记录级 AAD 完整性绑定；在相同密钥和应用 context 下，密文可能被跨列或跨行互换。
- **已缓解范围**：v2.2.1 仅提供应用级 context 绑定，不能消除此风险（证据：`c6006b2`、`4e428e6`）。
- **处置与验收**：设计可迁移的字段/记录级 AAD，并验证跨字段、跨记录和历史密文兼容场景。
- **目标版本**：待排期。
- **复查条件**：字段加密格式、AAD 或密钥迁移方案调整时，核对字段/记录绑定与历史密文兼容性。

<a id="td-023-rpc-hook-legacy-api"></a>

### TD-023：RPC Hook 旧 API 兼容

- **现状与风险**：`RpcHookChain` 废弃的 `before`、`after`、`onError`、`cleanup` 直调 API 仍可使用，绕开调用级 invocation 的生命周期约束。
- **已缓解范围**：框架内部已改用调用级 invocation，旧直调入口仅为兼容保留（证据：`bf493b6`、`2dd1b83`、`4e428e6`）。
- **处置与验收**：提供迁移路径和废弃周期；删除或隔离旧入口后，验证正常、异常和清理回调顺序。
- **目标版本**：待排期。
- **复查条件**：RPC Hook API 迁移、废弃或回调生命周期调整时，核对旧直调入口的迁移进度。

<a id="td-039-nacos-解密覆盖层"></a>

### TD-039：Nacos 解密覆盖层清理

- **已修复范围**：删除 Nacos 加密配置前缀时，刷新监听器清理旧 `decryptedProperties:*` 覆盖层；Environment 随后读取原始明文、下层配置或缺失值。聚焦的监听器测试和刷新集成测试覆盖了明文切换、下层回退、完全删除、重新加密及存在值时的 Bean 重新绑定。
- **剩余风险**：业务属性完全删除且没有下层值时，Spring Cloud 对已存在的 `@ConfigurationProperties` Bean 重新绑定后仍保留原字段值；本地负向测试已复现。该问题不再由解密覆盖层造成，但仍属于删除配置后的历史明文残留。
- **处置与验收**：确定缺失属性的 Bean 清空或重建策略，并验证无回退值时 Bean 不再保留旧明文；当前版本不能据覆盖层清理结果宣告本项全部完成。
- **目标版本**：待排期。
- **复查条件**：配置刷新、Bean 重新绑定或 Spring Cloud 基线调整时，复核完全删除且无下层值的旧明文残留。

<a id="td-043-jacoco-集成测试覆盖率"></a>

### TD-043：JaCoCo 集成测试覆盖率

- **历史问题**：JaCoCo `report` 曾绑定到 `test`，早于 Failsafe 集成测试，导致 XML 遗漏后续覆盖数据；历史重生成 Web 报告时，指令覆盖率从 `75.45%` 升至 `95.85%`，该数值不作为当前验收证据。
- **当前状态**：`mimir-boot-parent/pom.xml` 已将 `report` 和 `check` 绑定到 `verify`，读取同一 `jacoco.exec`，执行数据按追加方式写入。[治理计划 T3](./v2.3.0/docs-quality-governance/plan.md#t3-spotless覆盖率时序和报告完整性) 已记录仅由 IT 执行的类进入最终 XML 的本地专项验收；该记录不代表后续工具迁移或远程 CI 已验证。
- **最新证据**：2026-10-02 在固定提交副本复验仅 IT 方法的最终 XML 和真实阈值边界，见[专项记录](./v2.3.0/docs-quality-governance/verification.md#2026-10-02-专项复核与局部修复)。T8 期望矩阵等剩余条件仍未完成，本项继续开放。
- **处置与验收**：按[治理计划 T8](./v2.3.0/docs-quality-governance/plan.md#t8-独立验收与实施交付记录)完成工具迁移后的最终提交快照 full 和当前场景断言映射，复核最终 XML 含 Failsafe 覆盖数据以及报告收集/上传路径；不能仅凭普通 full 通过关闭本项，远程 CI 未核实时明确标记未验证。
- **目标版本**：待排期；关闭条件关联当前文档质量治理 T8，不以 `v2.3.0` 文档目录承诺发布版本。
- **复查条件**：T8 收尾或 JaCoCo、Failsafe、工程报告收集/上传流程调整时，核对本地专项证据与最终快照的一致性。

<a id="td-044-spotless-子模块门禁"></a>

### TD-044：Spotless 子模块格式门禁

- **历史问题**：根 POM 的 Spotless 活动配置 `__NO_SOURCES__` 曾被子模块继承，覆盖 Parent 的源码范围，造成检查未跳过但未扫描 Java 源码。
- **当前状态**：根 `pom.xml` 已设置该配置 `inherited=false`。[治理计划 T3](./v2.3.0/docs-quality-governance/plan.md#t3-spotless覆盖率时序和报告完整性) 已记录子模块 effective POM 源码范围及真实错误格式反例返回非零的本地专项验收；该记录不代表后续工具迁移或远程 CI 已验证。
- **最新证据**：2026-10-02 在固定提交副本复验 11 个源码模块配置及真实格式反例，见[专项记录](./v2.3.0/docs-quality-governance/verification.md#2026-10-02-专项复核与局部修复)。T8 全场景与最终快照条件仍未全部完成，本项继续开放。
- **处置与验收**：按[治理计划 T8](./v2.3.0/docs-quality-governance/plan.md#t8-独立验收与实施交付记录)完成工具迁移后的最终提交快照 full 和当前场景断言映射，以子模块源码范围与真实错误格式反例复核门禁；不能仅凭正常格式检查通过关闭本项，远程 CI 未核实时明确标记未验证。
- **目标版本**：待排期；关闭条件关联当前文档质量治理 T8，不以 `v2.3.0` 文档目录承诺发布版本。
- **复查条件**：T8 收尾或 Spotless、Maven 插件继承、格式检查入口调整时，核对源码扫描范围与真实负向结果。
